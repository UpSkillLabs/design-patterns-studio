Compile and Run Java 8–26 with Gradle

A self-contained setup guide for an IntelliJ IDEA Gradle project that can switch the JDK used to compile and run your application from Java 8 (1.8) through Java 26.

Build: Gradle Wrapper 9.7.1 Gradle JVM: JDK 21 Application JDK: 8–26 via toolchains DSL: Kotlin
Core rule: keep the JVM that runs Gradle separate from the JDK that builds and runs your application. Gradle 9.7.1 requires JVM 17–26 to execute, while project toolchains can select older JDKs for compilation and execution.

Prerequisites

Install IntelliJ IDEA and one modern JDK to run Gradle. This guide uses JDK 21 as the stable baseline for the Gradle JVM.

In IntelliJ IDEA:

File → Project Structure → SDKs → + → Download JDK
Version: 21
You do not need to manually install every JDK from 8 through 26. Gradle can auto-provision matching JDKs when a toolchain download repository is configured. Locally installed JDKs are also auto-detected.
2

Create the IntelliJ Gradle project

Create a new Java project:

File → New → Project

Language:      Java
Build system:  Gradle
JDK:           21
Gradle DSL:    Kotlin

Use the Gradle Wrapper as the distribution. The wrapper pins the Gradle version for the project and avoids relying on a machine-wide Gradle installation.

3

Set the Gradle JVM to JDK 21

Open:

Settings → Build, Execution, Deployment → Build Tools → Gradle

Set:

Distribution:   gradle-wrapper.properties / Wrapper
Gradle JVM:     JDK 21
Run tests using: Gradle
Do not set the Gradle JVM to Java 8. Gradle 9.7.1 requires a JVM between 17 and 26 to execute.
4

Configure automatic JDK provisioning

Replace settings.gradle.kts with:

plugins {
    id("org.gradle.toolchains.foojay-resolver-convention") version "1.0.0"
}

rootProject.name = "java-version-lab"

The Foojay resolver plugin gives Gradle a toolchain download repository. If a matching JDK is not already installed, Gradle can download one that satisfies the requested toolchain.

⚠️ Provisioning availability: a requested JDK still has to be available for your operating system and CPU architecture through the configured resolver. If provisioning fails, install that JDK locally and let Gradle auto-detect it.
5

Add a project Java-version property

Create or edit gradle.properties:

javaVersion=21

This is the normal day-to-day switch:

Java 8

javaVersion=8

Java 26

javaVersion=26
6

Configure build.gradle.kts

Replace build.gradle.kts with:

plugins {
    application
}

repositories {
    mavenCentral()
}

val targetJavaVersion = providers
    .gradleProperty("javaVersion")
    .orElse("21")
    .get()
    .toInt()

require(targetJavaVersion in 8..26) {
    "javaVersion must be between 8 and 26. Current value: $targetJavaVersion"
}

java {
    toolchain {
        languageVersion = JavaLanguageVersion.of(targetJavaVersion)
    }
}

application {
    mainClass = "org.example.Main"
}

tasks.withType<JavaCompile>().configureEach {
    options.encoding = "UTF-8"
}

The important part is the project toolchain:

java {
    toolchain {
        languageVersion = JavaLanguageVersion.of(targetJavaVersion)
    }
}

Gradle uses the configured toolchain for Java tasks that need JVM tools, including compilation and execution. The application plugin supplies the run task.

7

Create a Java program that reports its runtime

Create:

src/main/java/org/example/Main.java

Add:

package org.example;

public class Main {
    public static void main(String[] args) {
        System.out.println("Hello from Java");
        System.out.println("Java version : " + System.getProperty("java.version"));
        System.out.println("Java vendor  : " + System.getProperty("java.vendor"));
        System.out.println("Java home    : " + System.getProperty("java.home"));
    }
}

This example intentionally uses Java 8-compatible syntax so it can be compiled across the entire requested range.

8

Sync Gradle and inspect toolchains

In IntelliJ IDEA, use Sync Gradle Changes / Reload All Gradle Projects.

Then inspect the JDKs Gradle sees.

macOS / Linux

./gradlew -q javaToolchains

Windows PowerShell

.\gradlew.bat -q javaToolchains

The output shows auto-detection, auto-download status, and detected toolchain metadata.

9

Compile and run with Java 8–26

Temporary command-line override

You can override gradle.properties for a single invocation with -PjavaVersion=X.

GoalmacOS / LinuxWindows PowerShell
Compile with Java 8./gradlew clean compileJava -PjavaVersion=8.\gradlew.bat clean compileJava -PjavaVersion=8
Run with Java 8./gradlew clean run -PjavaVersion=8.\gradlew.bat clean run -PjavaVersion=8
Run with Java 17./gradlew clean run -PjavaVersion=17.\gradlew.bat clean run -PjavaVersion=17
Run with Java 21./gradlew clean run -PjavaVersion=21.\gradlew.bat clean run -PjavaVersion=21
Run with Java 26./gradlew clean run -PjavaVersion=26.\gradlew.bat clean run -PjavaVersion=26

The same pattern works for every integer Java version from 8 through 26:

./gradlew clean run -PjavaVersion=<8..26>

Build without running

./gradlew clean build -PjavaVersion=8
./gradlew clean build -PjavaVersion=26

Expected runtime verification

When running with Java 8, the program should report a Java 8 runtime. When running with Java 26, it should report Java 26. The exact vendor/version string depends on the JDK distribution selected by the toolchain resolver.

10

Recommended daily IntelliJ workflow

For normal development, change gradle.properties, then sync Gradle.

Develop against Java 8

javaVersion=8

Sync Gradle, write Java 8-compatible code, then run the Gradle run task.

Develop against Java 26

javaVersion=26

Sync Gradle again. IntelliJ imports the updated Gradle project model, and Gradle compiles/runs with the Java 26 toolchain.

Use gradle.properties for persistent IDE work. Use -PjavaVersion=X when you only need a one-off command-line test.

Run → Edit Configurations → + → Gradle

Run Java 8

Tasks:
clean run

Arguments:
-PjavaVersion=8

Run Java 26

Tasks:
clean run

Arguments:
-PjavaVersion=26
Editor caveat: a one-off Gradle run configuration changes that Gradle invocation; it does not necessarily make the editor behave as if the entire imported project has permanently switched language levels. For version-specific editing, change gradle.properties and re-sync the project.

Compatibility notes

Gradle runtime compatibility

For Gradle 9.7.1, the official compatibility matrix requires JVM 17 through 26 to execute Gradle. Java 26 support for running Gradle starts at Gradle 9.4.0.

Toolchain versus sourceCompatibility

Prefer Java toolchains when the goal is to select the actual JDK used by the build:

java {
    toolchain {
        languageVersion = JavaLanguageVersion.of(8)
    }
}

sourceCompatibility / targetCompatibility control source and bytecode compatibility but do not, by themselves, guarantee which JDK installation is used. Gradle's current documentation recommends toolchains for most users.

Toolchain versus --release

MechanismWhat it controlsUse it when…
Java toolchainSelects the JDK/tool set used to compile/run.You want to test against real JDK versions.
--releaseConstrains language/API/bytecode compatibility while using a compiler that may be newer.You need strict cross-compilation compatibility.

Dependencies can still block old Java runtimes

⚠️ Important: compiling your source for Java 8 does not make third-party libraries Java 8-compatible. Every runtime dependency must also support the selected Java version.

Version-specific syntax should fail where expected

If you switch to Java 8 and write syntax introduced later, compilation should fail. That is the intended behavior: the selected toolchain is enforcing the actual language/compiler environment.

Troubleshooting

“Gradle cannot run on this Java version”

Check the Gradle JVM in IntelliJ. Keep it on JDK 21 (or another supported 17–26 JVM for Gradle 9.7.1). Do not point Gradle itself at JDK 8–16.

No matching toolchain found

  1. Confirm the Foojay resolver plugin is present in settings.gradle.kts.
  2. Run ./gradlew -q javaToolchains.
  3. Confirm auto-download is enabled.
  4. If no matching downloadable JDK is available for your OS/architecture, install the JDK locally and re-run the toolchain report.

IntelliJ editor accepts/rejects the wrong syntax

Change javaVersion in gradle.properties and sync the Gradle project. Also inspect the module language level in Project Structure if the IDE model still appears stale.

Build works on Java 21 but fails on Java 8

Check both your source language features and all dependencies. A dependency compiled for a newer Java class-file version cannot run on Java 8.

Sanity checklist

  • Gradle JVM is JDK 21.
  • Gradle Wrapper is used.
  • Foojay toolchain resolver is configured.
  • javaVersion is between 8 and 26.
  • Gradle project has been synced in IntelliJ.
  • javaToolchains reports the expected JDKs or provisioning settings.
  • run prints the expected runtime Java version.
